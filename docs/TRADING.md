# Регламент торговой сессии (для агента Claude)

Команды пользователя: «начинаем торговлю» -> СТАРТ. «заканчиваем» -> СТОП. Без этих команд ордеров не открывать.
Все лимиты — в config/config.json. Менять их можно только по прямому указанию пользователя.

## Регламент входа и режим эксперимента (актуально с 2026-10-27, Bybit; ниже старые разделы про платформу кошелька)
Первая неделя (до 2026-11-03) = эксперимент: цель проверить или опровергнуть гипотезы, а не гнаться за прибылью; много ошибок ожидаемо и нормально, если они записаны и разобраны. Прибыль желательна, но не ценой отказа от правил и сбора данных. Решение пользователя 2026-10-27.
1. Перед лимитным входом у уровня нужна реакция цены (шорт: 5-минутная свеча закрылась ниже уровня после прокола; лонг: выше). Идея фиксирует это в `--note` (что жду). Вход без подтверждения допустим только как осознанный эксперимент: риск вдвое меньше обычного и тег `no-confirm` в разборе.
2. Стоп за экстремум отката, не над зоной. Если стоп получается шире допустимого для типа сессии (`max_stop_pct`), сделку пропускаю, а не сжимаю стоп.
3. После стопа по монете в неё не входить 30 минут; после двух стопов подряд общая пауза 1 час, и вход только со свечным подтверждением.
4. Перед входом: `./tb bybit trade open ... --dry-run` (guard) и сверка с ctx: спред и диапазон 5м. Если диапазон 5м шире стопа, пропускаю.
5. Каждая сделка и каждая идея записываются с гипотезой; после закрытия разбор `./tb journal post` (теги ошибок, правило соблюдено, урок). Статистика: `./tb journal analyze`, `./tb ideas stats`. Выводы делаем не раньше 30 закрытых сделок; правила меняем только по данным, заранее записав, что проверяем.
Не меняются: лимиты риска, плечо и размер (только по прямому указанию пользователя), без усреднения и мартингейла. Уроки: `docs/LESSONS.md`.

## СТАРТ
1. `perps_readiness` (ok:true), `get_server_time`, `balance_get`, `perps_list_positions`.
2. Собрать equity: баланс USDT + маржа открытых позиций (+ нереализованный PnL, если считается).
3. `echo '<snapshot json>' | ./tb tick --start` (фиксирует day_start_equity, обнуляет дневные счётчики).
4. Включить цикл: каждые 60 с выполнять ТИК. Мониторинг — это и есть цикл, отдельных наблюдателей нет.
5. Сообщить пользователю: сессия включена, лимиты (маржа на сделку, дневной лимит убытка, макс. позиций).

## ТИК (каждые ~60 с)
1. `perps_latest_rate` по символам из config (ETH-USD-PERP, BTC-USD-PERP), `perps_list_positions`, `balance_get`;
   funding и параметры контрактов брать из кеша `perps_list_contracts` (обновлять раз в час, не каждый тик).
2. Собрать JSON по SPEC.md -> `./tb tick` -> прочитать `halt` и `decisions`.
3. `halt=true` -> закрыть все позиции (prepare_position_close -> execute), цикл остановить, написать пользователю причину.
4. По каждому решению: `open` -> `perps_prepare_order_place` (market, autoClose stop+tp) -> если preview.ok сразу
   `perps_execute_operation`; `close` -> `perps_prepare_position_close` -> execute; `set_auto_close` ->
   `perps_prepare_auto_close_set` -> execute. Токен живёт ~90 с, исполнять сразу.
5. После записи ордера сверить `perps_list_positions`. Ошибку execute НЕ повторять вслепую: перечитать
   позиции/ордера, затем решать. `agent.trading_disabled` -> остановить цикл и сообщить.
6. Любая неопределённость (пустой ответ, расхождение позиций, неизвестная ошибка) = не открывать новое, сообщить.

## СТОП
1. `./tb tick --stop` -> `flatten`; закрыть все позиции, подтвердить пустой `perps_list_positions`.
2. Остановить цикл.
3. `./tb tick --report` и показать итог дня: PnL, число сделок, причины входов/выходов, комиссии, funding.

## Чего не делаю никогда
- Не увеличиваю лимиты, плечо и маржу сам; не усредняю убыточные позиции; не торгую вне сессии.
- Не переводю и не вывожу средства (таких инструментов нет и не будет).

## Экономия токенов и времени
- Простой = ноль токенов: в сессии торговля идёт по событиям из `runtime/events.jsonl` (Monitor), а не по таймеру.
  Минутный cron-сборщик цен через MCP отключается, как только работает `marketdata/feed.py`.
- Тик исполняется механически: события -> один вызов `legacy_engine/tick.py` -> по каждому решению ровно prepare + execute.
  Без рассуждений и пояснений в чат; сообщения пользователю только при открытии/закрытии, halt, ошибках и в итоге дня.
- Размер и плечо считает `legacy_engine/sizing.py` (риск = доля equity, стоп из ATR, режим рынка, потолки из config); я их не пересчитываю.
- Субагенты: только для новых модулей, короткий бриф с контрактом, дешёвая модель для механической работы,
  без повторных запусков «на проверку». Проверка результата — запуск тестов, а не чтение кода.
