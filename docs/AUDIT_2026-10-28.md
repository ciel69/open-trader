# Аудит алгоритмов и метрик «пора торговать / не пора» (2026-10-28)

Разбор кода и данных за 27-28.10: сканер, guard, досье и роли мозга, исполнитель, статистика исходов. Цель: найти узкие места, из-за которых хорошие входы не случаются, плохие проходят, а статистика не даёт ответа. Файлы кода не менялись. Все выводы по данным (1 137 событий сканера, 7 сделок) предварительные: выборка 1 день, кластеризована по часам.

## Главный вывод

Механика риска (guard, стопы в ордере, лимиты) работает корректно. Слабое место не в ней, а в трёх вещах:

1. Сканер измеряет «шум» (диапазон, оборот), а не асимметрию. По данным самые «громкие» события (score >= 6, именно те, что будят агента при `--wake-score 7`) в среднем откатывают, а не продолжаются: продолжение за 15 мин -0.77 % брутто (n=64), за 60 мин -0.56 %; откат после издержек +0.3…+0.5 %. Значимости нет (t около -1.3, 13 кластеров), но это единственная гипотеза с ненулевым сигналом, и рамка «вход по направлению импульса» ей противоречит.
2. Конвейер мозга теряет данные о монете события: монеты для блока структуры выбираются по алфавиту, а не по событию; само событие вытесняется из `recent`; ответы модели обрезаются по лимиту вывода. Из 22 решений entry_scout 0 предложений, 19 skip, большинство skip с формулировкой «нет структуры», хотя структура по монете была.
3. Обратная связь измеряет не то, что торгуется: исходы считаются «вход по цене события, выход через 15/60 мин», без пути цены (MAE/MFE), с константными издержками и iid-ошибкой. Проверить стратегию «лимит у уровня, стоп за экстремум» на этих данных нельзя.

## Узкие места потока решений (почему входов мало)

- Будят «после рывка». range_5m по определению = свеча уже прошла >= 0.8 %, то есть роль просыпается, когда правило «не гонись» уже нарушено. Триггера «цена вернулась к уровню после рывка» нет, хотя уровни в `structure.json` есть.
- Треть сигналов не доходит до модели: cooldown 1200 с/монета, 12/ч сканер, 20/ч диспетчер, 20/ч роль, 4 плана/ч; плюс morning_analyst (до 4 раундов, минуты) занимает воркер, задание ждёт 75 с и данные устаревают.
- Роль entry_scout видит одну монету, два уровня, без свечей, OI, стакана, идей дня и плана дня. Промпт требует сетапы reclaim/sweep/retest и `swing_5m` из `levels`, которых для монет сканера не бывает никогда (`executor/mdsvc.py:94-96` пишет levels только по символам планов).
- Размер при счёте 39 USDT определяется не риском, а потолком маржи 6 USDT x плечо и множителями: `score` по умолчанию 0.5 (x0.75), probation x0.5, no-confirm x0.5. Риск 0.2-0.4 USDT при комиссиях 0.03-0.05: 10-25 % риска уходит в комиссии, при RR 1.5 ожидание съедается. Бюджет intraday-сессии (3 % = 1.17 USDT) равен одному полному риску: после двух стопов сессия закрыта.
- Издержки: taker-круг 0.24 % против maker 0.072 %. При валовом ожидании сигналов около нуля это главный рычаг: единственные плюсовые сделки в журнале помечены `maker`.
- Исполнитель не проверяет спред при активации (только валидность bid/ask), STALE 3 с для входа на тихих альтах, инвалидация в позиции = рыночное закрытие по last без буфера.

## Мёртвое и непроверенное

Не используется: `patterns.py` (только CLI; research дал «нет» по 9 гипотезам), `watch.py`, `volwatch.py`, события фида в `runtime/events.jsonl`, `cvd/imbalance/oi_chg_5m`, `context.derivs/global`, `day_limits.json`, блок `levels` для монет сканера. Используется, но не калибровано: пороги режимов (`TREND_ATR_MULT`, `STORM_VX`, `storm_rv_5m`), `risk_off` по DVOL/F&G, весь блок `struct`.

## Что делать (по эффекту на стоимость)

Исправления без изменения торговых правил (чинят поток и измерение). Пункты 1-3 сделаны 2026-10-28 (см. docs/BRAIN.md, тесты test_brief / test_brain_entry / test_llm_adapters):

1. `brief.py`: `ev_syms` из wake-события задания, не по алфавиту; события `job.seqs` всегда в `recent`.
2. entry_scout: `max_output_tokens` ~2000 при thinking или прибавлять бюджет thinking в openai_compat; после `length` менять параметры, а не повторять.
3. `validate.dayplan_context`: символы из struct/hot/ideas; пороги RR/стопа из `session_types`; `day_limits.json` в scope=event и проверка allowed_setups/avoid.
4. Funding: интервал из instruments-info (сканер уже кэширует), одна размерность `fu` в досье.
5. Исходы: p0/p1 по bid/ask, издержки со спредом, MAE/MFE по сканам между ts0 и горизонтом, кластерная SE и дедуп по монете за 15 мин. Без этого гипотезу «откат после громких событий» проверить нельзя.
6. Единый R (guard `risk0` в журнал), funding в PnL, BE по фактическим комиссиям обеих сторон, STOP_RATE не для трейла, CHASE от уровня триггера.

Изменения торговой логики (только после п. 5 и по данным):

7. Триггер «возврат к уровню после рывка» вместо/в дополнение к range_5m: цена в зоне res/sup из `structure.json` после импульса >= X; либо роль отвечает `watch` с уровнем и код сам ставит план с `candle_close` (entryplan это уже умеет).
8. Maker-вход как режим по умолчанию (post-only у уровня с TTL): снижает круг с 0.24 % до ~0.14 % и единственное, что в журнале давало плюс.
9. Проверить на накопленных исходах с MAE/MFE гипотезу fade для score >= 6 и |chg_24h| >= 30 % со стопом за экстремум; по правилам RESEARCH.md (train/test, кластерная SE). Не торговать до проверки.
10. Пересмотреть множители размера для эксперимента: score по умолчанию 0.5 даёт x0.75 без причины; probation x0.5 и no-confirm x0.5 вместе дают риск, где комиссии >= 15 %. Это решение владельца, не агента.

Что я не проверял: исполнение на бирже вживую, точность `structure.analyze` на реальных свечах, промпты news_reader.
