# WP1B: проверка на testnet

Дата: 2026-10-28. Площадка: Bybit **testnet** (SOLUSDT). Отдельный корень `TB_ROOT=<scratchpad>/tn` (копия `config/`, пустой `state/`, сессия intraday 120 мин, `watch_symbols=[SOL]`, `portfolio.json` с equity как на бирже 9978 USDT). Исполнитель: `./tb exec run --profile testnet --max-seconds 900` (фоном), старые команды: `./tb bybit testnet ...`. Mainnet не вызывался, ключи не читались. В конце: позиций и ордеров на testnet нет, процессов нет, реальный `state/` не тронут.

## Замеры и наблюдения
- Задержка записи (`exch_ms` в журнале решений): place_entry 780-986 мс, place_target 470-610 мс, close 1.8 с и один выброс 11.5 с (зависание стороны биржи, как в WP1A T10 / WP5). Keep-alive экономит только TLS-рукопожатие, на testnet выигрыш небольшой; радикально сокращает хвост не транспорт, а то, что защиту держит стоп на бирже.
- `guard_preview` теперь показывает `reasons`, когда вход невозможен (MIN_SIZE: при `--size-mult 0.003` и бюджете сессии 1.2 USDT размер получался 0.0 < 0.1 SOL, preview раньше выглядел как `{"ok": true}`).
- Перед стартом исполнителя в новом корне на testnet совпал `orderLinkId` (`tbx-3-1`, код 110072): счётчик `plan_n` нового корня начинается с 1, а на аккаунте testnet остались ордера прежних прогонов. Для проверки счётчик подняли до 8000. В боевом корне счётчик непрерывен; но при заведении НОВОГО корня на тот же аккаунт номер стоит сдвигать (см. риски в отчёте).
- Расхождение суммы equity (`equity_mismatch`: portfolio.json 40 против 9978 на бирже) держит вход до ближайшей синхронизации (до 300 с): ожидаемое поведение WP5.
